# Trucker Helper 插件 — 功能与使用说明

适用版本：v0.7.5（2026-10-20）

Trucker Helper 是一个 Chrome 插件：输入柜号后，自动从金山文档「提柜」表查出 MBL 和船公司（SSL），再按船公司的方式向对方询问 **Last Free Day（LFD）** 或提交 **On-Hire** 请求——发邮件、提交工单网站或在线客服聊天。插件**只负责发出询问**，对方回复的 LFD 日期仍需你在邮箱 / 聊天窗口中查看。

## 1. 安装与更新

### 安装

1. 将安装包 `lfd-inquiry-extension-vX.Y.Z.zip` 解压到一个**固定的文件夹**（以后不要移动或删除）。
2. Chrome 打开 `chrome://extensions`，打开右上角「开发者模式」。
3. 点「加载已解压的扩展程序」，选择解压后的文件夹（文件夹里直接是 `manifest.json`）。
4. 点击工具栏上的 Trucker Helper 图标，底部显示版本号即安装成功。

### 更新

把新版本的文件解压覆盖到原文件夹，然后在 `chrome://extensions` 中点该插件的「重新加载」。**不要卸载重装**——卸载会清空发送记录和防重复锁。

> 换电脑或新装插件时，原来的记录不会带过去；航司配置请用「导出 JSON / 导入 JSON」迁移（见第 10 节）。

## 2. 首次配置

打开插件 →「配置」页：

| 项目 | 说明 |
| --- | --- |
| 船公司配置 | 插件自带 12 家船公司的配置。每家船公司有自己的称呼，以及按查询类型分开的收件人 / 抄送 / 主题 / 正文；识别别名、MBL 前缀、发送方式在「高级设置」里 |
| 连接与默认选项 | 提柜表链接、Gmail 账号编号（`/u/` 后的数字，决定用浏览器里第几个账号写信）、默认船公司、默认查询类型、**邮件发送方式** |
| 导入 / 导出配置 | 导出 JSON 备份；把 JSON 内容粘贴进导入框立即生效；「恢复默认配置」回到内置内容 |

配置页**没有保存按钮**：改动约 0.4 秒后自动保存，右上角显示「已自动保存」。暂时填不完整的内容（如只打了一半的邮箱）显示「未保存：原因」，这部分内容留在本机，关掉弹窗再打开还在，补全后自动保存。重新打开弹窗会回到上次的页面、船公司、查询类型和滚动位置。
| 系统通知 | 「发送测试通知」检查通知点击是否有效 |

需要在这台 Chrome 中登录：

- **金山文档**（能编辑「提柜」表的账号）——插件读表需要。
- **Gmail**（如使用 Gmail 网页发信）。

> **只读脚本会自动安装**：插件第一次读表时，会在你账号的金山 AirScript「我的脚本」里自动新建 / 升级 `LFD_ReadOnly_v1`，无需手动复制。前提是你对表格有编辑权限。中文、英文界面的金山文档都支持。

## 3. 日常查询流程

1. 在「查询」页的柜号框**粘贴柜号**（约 0.7 秒后自动查询），或点「查询」。
2. 插件**先查本地缓存**，缓存里没有才读取金山文档「提柜」表。查询期间输入框不会锁定，可以继续输入其他柜号。
3. 显示匹配结果：船公司、MBL、来源行号，右侧显示邮件 / 工单 / 聊天预览。
4. 选择查询类型（Demurrage / Detention / On-Hire），确认预览后点发送按钮。
5. 发送作为**后台任务**执行，弹窗马上可以继续查下一个柜号；进度在「进行中」页签查看。

### 查不到的情况

- **柜号在缓存和表里都找不到**：弹出「找不到该柜号」——「确定」清空输入，「再次查找」重新读一次表（插件不会自动重复读表）。
- **查到了但缺 MBL 或船公司**：可以在「MBL」框手动填写、在「船公司」下拉框手动选择，然后再发送。
- **识别出的船公司还没配置**：提示「首次使用：请补充配置」，点按钮跳到配置页。COSCO、ONE 等内置船公司会自动带出默认配置。

## 4. 查询类型

| 类型 | 用途 | 说明 |
| --- | --- | --- |
| **Demurrage** | 码头免费期 LFD | 邮件 / 在线客服 |
| **Detention** | 箱子免费期 LFD | 邮件 / 在线客服；COSCO 固定为 Detention 工单 |
| **On-Hire** | 申请 on-hire（还空箱到指定码头） | 每家船公司有独立的 On-Hire 收件人和模板；**支持一次多个柜号** |

同一个柜号的 Demurrage、Detention、On-Hire **分别防重复**，可以各发一次。

### 模板占位符

| 占位符 | 内容 |
| --- | --- |
| `{{steam shipping line}}` | 船公司称呼（如 MSK、Cosco） |
| `{{carrier}}` | 船公司名称 |
| `{{type}}` / `{{Type}}` | 查询类型（demurrage / Demurrage 等） |
| `{{container}}` | 柜号（多柜号时逗号分隔） |
| `{{mbl}}` | MBL（多柜号时逗号分隔、去重） |
| `{{table}}` | Container# / MBL# 表格（每个柜号一行） |

默认邮件模板：

```
主题：{{Type}} Trucker Helper - Container#{{container}} MBL#{{mbl}}

Dear {{steam shipping line}},

Could you please advise the {{type}} LFD for the container below?

{{table}}
```

默认 On-Hire 模板（未填写时使用）：

```
主题：On-Hire Request - Container#{{container}} MBL#{{mbl}}

Dear {{steam shipping line}},

Please on-hire below containers to Terminal A, B,C,D,...,etc.

{{table}}
```

## 5. 各船公司的发送方式

### 5.1 邮件（大多数船公司）

在「连接与默认选项 → 邮件发送方式」中选择：

#### Gmail 网页（推荐、默认）

- 插件在后台打开 Gmail 写信页，填好收件人、抄送、主题和带表格的正文，**保留 Gmail 原签名**（账号没设签名也可以发送），然后自动发送。
- 发送后要等 Gmail 自动关闭写信页才记为「已发送」，防止「显示已发送但实际没发」。
- 只要求配置的 To / Cc 都在写信页上；其他插件额外加的抄送 / 密送不会阻止发送。

#### 电脑默认邮件程序（自动填写，手动发送）

插件通过邮件链接打开**Windows 默认邮件程序**的写信窗口，自动填好收件人、抄送（分号分隔）、主题和正文。**最后由你在邮件程序里点发送**，发完回插件点「我已发送」。

再选择「邮件程序」——必须与 Windows 默认邮件程序一致：

| 邮件程序 | 正文格式 |
| --- | --- |
| **Foxmail**（默认） | 正文分行 + 带边框的 Container# / MBL# 表格 |
| **Outlook** | 纯文本，柜号以「Container#: … / MBL#: …」逐行显示（Outlook 不显示表格） |

注意：

- 插件**只能打开 Windows 默认邮件程序**，不能指定其他程序，也无法检测是否已安装。配置页有「下载 Foxmail」「下载 Outlook」和「打开 Windows 默认应用设置」入口（在设置里搜索 **MAILTO** 选择程序）。
- 插件**无法知道邮件是否真的发出**，必须手动点「我已发送」。
- 签名由邮件程序自己添加。
- 第一次使用时 Chrome 会询问是否打开外部程序，请勾选「始终允许」。

### 5.2 COSCO — 工单网站

| 查询类型 | 网站 | 自动填写的字段 |
| --- | --- | --- |
| Detention（LFD） | support.cosco-usa.com | Requester、Shipment Type = Per Diem、Per Diem Services = Last Free Day（PD INV/BL/BKG/HOU # / SCAC Code 可选，默认不填）、Description（带表格） |
| On-Hire | coscoshippingla.freshdesk.com | Requester、Type = Equipment、Services = On / Off Hire、Region = Southern California、Number of Containers、Container #（空格分隔）；SCAC Code 可选，默认不填、Description（带表格） |

- 工单在浏览器右下角的**小窗**里填写，不占用你的标签页。
- **人机验证（I'm not a robot）必须你手动勾选**——插件不会也不能自动通过。到这一步小窗会弹到最前面；被挡住时会弹出系统通知「COSCO 工单等待人机验证」，点通知或「进行中」里的「去验证」回到小窗。
- 勾选后插件**自动点 Submit**，确认提交成功后记录工单号并关闭小窗。
- 3 分钟内没完成验证：工单不提交，记录为「工单未提交」，小窗保留，可以手动提交。
- COSCO 的 On-Hire 默认 Description：`Dear Cosco, Please onhire below containers to LBCT,PCT,ETS,FMS,APM` + 表格，可在 COSCO 配置的 On-Hire 正文模板中修改。

### 5.3 ONE — 在线客服聊天（Demurrage / Detention）

- 插件在小窗里打开 one-line.com 在线客服：选国家（United States）→ ONE Chat → 填写 First Name / Last Name / Email、Reference Type = Container Number、柜号 → Start the Chat → Import → Last Free Day / Demurrage & Detention → FINISHED MY INQUIRY → Transfer to a Customer Care Agent。
- **客服接入后立即发送**消息 `Please advise {{type}} LFD for {{container}} / {{mbl}}`；客服**已读（Read）** 才记为「已查询」。
- 已读后插件继续关注对话最多 15 分钟，**客服回复时弹出系统通知**，点通知打开只显示聊天框的小窗查看 LFD。
- **对话复用**：同一浏览器里 ONE 同时只能有一个对话。上一个对话窗口还开着且客服还在时，新柜号直接**追加到这个对话**；客服已结束对话或窗口已关闭时，开新窗口、新对话。ONE 任务按顺序排队执行。
- ONE 的 **On-Hire 走邮件**（ONE 配置里的 On-Hire 收件人和模板）。
- 小窗默认只显示聊天框。如果聊天窗口加载失败，小窗会显示 ONE 原页面以便查看原因（如不在服务时间、维护中）。
- 可配置：First Name（默认 LET）、Last Name（TANG）、Email、Country、消息模板。

### 系统通知与小窗

| 场景 | 通知 | 点通知 |
| --- | --- | --- |
| COSCO 等待人机验证 | 「COSCO 工单等待人机验证」 | 打开工单小窗 |
| ONE 客服回复 | 「ONE 客服已回复」+ 回复开头 | 打开聊天小窗 |
| ONE「转人工但不发送」客服接入 | 「客服已接入，消息已填好未发送」 | 打开聊天小窗 |

Chrome 插件窗口无法「始终置顶」，小窗被挡住时请用通知或「进行中」里的按钮调回。

## 6. 一次处理多个柜号

适用于 **On-Hire**（所有船公司）和 **ONE** 在线客服。

- **粘贴一段文字**到柜号框（例如 `OOLU9995789 FFAU8502590 OOCU5752763 …`，可以是空格、换行混合），插件自动识别所有柜号：第一个放主框，其余每个自动新增一行，并逐个查 MBL 和船公司。
- 也可以点柜号框里的 **＋** 手动加一行（只在 On-Hire 或 ONE 时显示）。
- 以**第一个柜号的船公司为基准**，船公司不同的柜号框显示**红色边框**并提示删除；有红框、找不到或仍在查询的柜号时不能发送。
- 每个框都可以删除，包括第一个（删除后下面的柜号往上补）。
- 发送时：
  - **On-Hire 邮件**：一封邮件，表格每个柜号一行（最多 30 个）。
  - **COSCO On-Hire**：一张工单，Container # 列出全部柜号。
  - **ONE**：同一对话里**每个柜号单独一条消息**，全部已读才算完成（最多 10 个）。
- 每个柜号各自记录、各自防重复。

## 7. 后台任务：「进行中」页签

所有发送 / 草稿都是后台任务，点击后弹窗立即可用。

**进行中**：显示柜号、船公司、类型、开始时间和当前步骤（如「填写聊天表单」「等待客服接入」「等待人机验证（小窗）」「等待客服已读（1/2）」），以及：

- **打开页面 / 打开聊天 / 去验证**：调出对应的小窗或标签页。
- **终止**：关闭任务窗口并停止。未发出的记为未发送；已发出的记为待核实。

**需要处理**：所有未完成、待核实、中断、等待「我已发送」的任务：

| 按钮 | 作用 |
| --- | --- |
| 我已发送 | 邮件程序方式发完后确认 |
| 我已核实已发送 | 核实确实已发出后点击，改为已发送，**保留防重复锁** |
| 重新发送 | 解除锁定，并把柜号和类型填回查询页，确认后再发送 |
| 删除 | 解除锁定并归档（之后可以重新发送） |
| 重新打开邮件 | 邮件程序方式的写信窗口被关掉时重新打开 |

关闭弹窗不会中断后台任务；插件后台被 Chrome 重启而中断的任务会显示「已中断，请打开页面核实结果」。

## 8. 操作记录与防重复

- 防重复依据：**柜号 + MBL + 船公司（或码头）+ 查询类型**，和用哪个 Gmail 账号发送无关。同一组合已有草稿、已发送或待核实记录时，不会再次发送。
- 被挡住时弹出「已有记录，未发送」，列出柜号、状态和时间：
  - **强制重发**：解除旧记录锁定并立即重新发送（旧记录归档）。如果之前其实已经发出，对方会收到重复邮件 / 消息。
  - **查看记录**：跳到「记录」页。
- 「记录」页显示所有记录及状态；「解除锁定」把记录归档并允许重新发送。

记录状态：

| 状态 | 含义 |
| --- | --- |
| 草稿已生成 / 已填写未提交 | 点了「仅生成草稿」或用邮件程序方式，尚未发送 |
| 已发送 / 已查询 / 工单已提交 | 确认已发出 |
| 发送结果待核实 | 已开始发送但没能确认结果，请到对应页面核实 |
| 未完成 | 发送前出错，未发出 |

## 9. 仅生成草稿

**主按钮会真实发送**，不再有测试模式。想先检查时点主按钮下面的按钮：

- Gmail：「仅生成草稿」，生成草稿，不发送。
- COSCO：「仅填写工单」，填好工单，不提交。
- ONE：「转人工但不发送」，走完菜单、转人工，客服接入后把消息**填入输入框但不发送**（注意：会真实联系一位客服）。
- 邮件程序：打开写信窗口，本来就由你手动发送。

## 10. 配置页功能一览

| 功能 | 说明 |
| --- | --- |
| 航司模式 / 码头模式 | 右上角切换。两种模式配置分开保存；码头没有内置内容，需要自己添加码头和它的查询类型 |
| 新增 / 删除船公司或码头 | 「＋ 新增」输入名称后点「添加」才创建，同名的不会重复创建；删除立即生效 |
| 查询类型 | Demurrage / Detention / On-Hire 各自有 To、Cc、主题、正文；「＋ 新增类型」添加自定义类型，用法相同。新类型的 Cc 默认填好 service@darwinpacific.com 和 truck@darwinpacific.com |
| 使用标准模板 | 一键填入当前类型的默认模板 |
| 高级设置 | 当前类型的发送方式（只有 COSCO 和 ONE 有这一项：COSCO 工单 / ONE 在线客服 或邮件，其他船公司只发邮件）、表中别名、MBL 前缀、工单和聊天参数。码头模式没有这一项 |
| 连接与默认选项 | 提柜表链接、Gmail 账号编号、默认船公司 / 查询类型、邮件发送方式 |
| 导入 / 导出配置 | 导出 JSON；把 JSON 内容粘贴到导入框后立即替换配置（旧版文件也可以，码头配置和操作记录保留）；「恢复默认配置」 |
| 缓存、通知与脚本 | 清除本地缓存、发送测试通知、复制 / 下载只读脚本（脚本通常不用手动处理，插件会自动安装） |

导入用粘贴而不是选文件，是因为在 Windows 上弹窗里打开系统文件选择框会让弹窗白屏关闭。

### 界面语言

右上角可切换 中文 / English / Español，即时生效并记住选择。没选过时跟随浏览器语言：中文浏览器用中文，西班牙语浏览器用 Español，其他用 English。邮件内容和模板不翻译。

### 实验性功能：Gmail 自动抄送（Auto CC）

默认关闭，在「配置 → 实验性功能」里手动开启。

- 填写**发件人**和**抄送对象**。在 Gmail 里写信或回复时，只有发件人在名单里才自动加上抄送。
- 其他发件人、或插件判断不出发件人时，不做任何改动，也不提示。发件人名单为空时不会添加。
- 收件人里已有的地址不重复添加；你手动删掉的地址在这个写信窗口里不会再加回来。
- 开启后 Gmail logo 右侧出现「Auto CC」按钮，点击打开插件配置并定位到这一项（打不开弹窗时开一个小窗口；配置页已打开时直接切过去，不会重复打开）。改动实时同步到已打开的 Gmail 页面和插件窗口。
- 插件自己发的 LFD 询问邮件不走这个功能，抄送仍按船公司配置。

限制：
- 抄送在写信窗口打开时加入。在窗口里把发件人改成名单外的账号，已加的抄送**不会自动去掉**，需要手动删除。
- 刷新或重新加载插件后，已打开的 Gmail 页面要刷新一次才生效。

### 码头模式

查询方式和航司模式相同，但提柜表没有码头信息，所以不会自动识别，需要在查询页选择码头。码头只走邮件，发送规则和船公司相同。

### 船公司识别规则

1. 优先用表中 SSL 列匹配船公司的名称、ID 或别名（如「COS」→ COSCO，「ONE」→ ONE，「MSK」→ Maersk）。
2. 表中没有 SSL 时按 MBL 前缀识别（如 MAEU → Maersk，MEDU → MSC，COSU → COSCO，ONEY → ONE）。
3. 匹配到多个、或 SSL 与 MBL 前缀冲突时，要求手动选择。
4. 手动选择的船公司优先于自动识别。

## 11. 提柜表读取规则

- 只读取名为「**提柜**」的工作表，按表头识别「柜号 / MBL / 船司」列。
- 柜号必须是 4 个字母 + 7 位数字。
- 遇到「**取消DO**」行，跳过这一段，直到下一个「已送仓」或「排程:」标题再继续读取。
- 同一柜号有多行时，取表格从上往下**第一条 MBL 和 SSL 都不为空**的整行，不跨行拼接。
- 缺 MBL 或 SSL 的行不写入本地缓存。
- 多个柜号同时查询、缓存都没有时，只读一次表、结果共用。
- 读表失败不会清空已有缓存。
- **插件只读表格**：不写单元格、不排序、不切换工作表，不删除任何行。

## 12. 安全与权限

| 权限 | 用途 |
| --- | --- |
| storage / unlimitedStorage | 保存配置、缓存和记录（仅本机） |
| scripting | 在金山文档、Gmail、COSCO、ONE 页面中自动填写 |
| notifications | COSCO 验证、ONE 回复提醒 |
| 网站权限 | mail.google.com、www.kdocs.cn、support.cosco-usa.com、coscoshippingla.freshdesk.com、www.one-line.com、one-line.my.site.com 等 |

- 插件不保存、不读取任何密码或邮箱授权码；使用的是你在 Chrome 里已登录的会话。
- 后台只接受插件自己页面发来的请求。
- 邮件、工单、聊天内容由模板生成并做转义，不会执行任意代码。
- 人机验证由你本人完成。

## 13. 已知限制

- **网站改版**：金山文档、Gmail、COSCO、ONE 页面结构变化可能导致自动操作失败，插件会停下并提示，不会乱填。
- **邮件程序方式**只能打开 Windows 默认邮件程序，无法确认是否已发出；Foxmail 和 Outlook 的正文格式不同，需要在插件里选对。
- **ONE**：同一浏览器同时只能有一个对话；不在服务时间时无法联系客服。
- **COSCO**：人机验证必须手动完成。
- 插件**不会自动读取对方回复的 LFD 日期**。
- 卸载插件会清空记录；换电脑不会带走记录。

## 14. 常见问题

**Q：显示「已有草稿、发送或待核实记录」，发不出去？**
A：点弹出框里的「强制重发」，或到「进行中 → 需要处理」点「重新发送」/「删除」。确认之前确实没有发出再操作。

**Q：「找不到该柜号」，但表里明明有？**
A：检查柜号是否在「取消DO」段内、柜号格式是否标准（4 字母 + 7 数字，无空格）、是否在「提柜」工作表。

**Q：ONE 小窗白屏 / 提示没有加载出聊天窗口？**
A：打开小窗看 ONE 页面上的提示（可能不在服务时间或维护中），稍后在「需要处理」里点「重新发送」。

**Q：Foxmail 正文挤成一行，或 Outlook 显示 `<br>`？**
A：「连接与默认选项 → 邮件程序」选错了，请改成与 Windows 默认邮件程序一致的那个。

**Q：点通知没反应？**
A：在「配置 → 系统通知」点「发送测试通知」检查；并确认 Windows 允许 Chrome 显示通知。

**Q：导入配置时弹窗白屏？**
A：从工具栏弹窗点「选择 JSON 文件」会打开一个完整的插件页面，请在那个页面里选择文件导入。

**Q：Gmail 报「收件人与配置不符」？**
A：提示里会写明缺少哪个地址；检查船公司配置中的 To / Cc，或 Gmail 写信页中是否有地址被删除。

**Q：COSCO 人机验证小窗找不到了？**
A：点系统通知，或「进行中」里的「去验证」。
