## 2. 用户目标与明确反馈

- 用户使用插件打开 Windows Foxmail 写信窗口，希望一次点击自动填好 To、Cc、主题及带正确换行的正文，保留现有 Foxmail 签名。
- 用户明确说“不要手动复制”。复制按钮、让用户 Ctrl+V 都不是最终可接受方案。
- 本次范围是自动填写；最后由用户在 Foxmail 点击发送。不得自动点击发送，不得将成功打开窗口当成发送成功。
- 用户希望在配置页选择邮件发送方式并保存时，能够开始辅助程序安装流程。
- 用户关心是否仅安装一次，以及为何要限制 Foxmail。应明确解释常规升级无需反复安装的设计目标，但不得承诺任何环境下永久免维护。
- 当前优先目标是 Foxmail；架构可扩展其他客户端。不能宣称通用“默认邮件程序”模式已支持 Outlook 等客户端的自动填写。

## 4. 期望交互

建议新增明确的发送方式“Foxmail（自动填写，手动发送）”，保留 Gmail 和原有默认程序方式的兼容性。

保存该选项时：
1. 检测本地助手是否存在、版本兼容、是否可通信。
2. 可用：保存并显示就绪。
3. 不存在：显示安装说明及安装按钮，引导下载安装包。用户需亲自运行安装程序；不能承诺浏览器静默安装 EXE。
4. 安装完点击“重新检测”（或进行有界重试），成功后再显示就绪。
5. 安装取消或失败：显示具体原因及重试入口，不假装已启用；不要丢失其他配置。

日常使用：
1. 复用插件已确认的柜号、MBL、航司及模板，不为打开 Foxmail 重复查表。
2. 由助手创建新写信窗口，确定正确发件账号。
3. 分别填入 To/Cc、主题及格式化正文，保留该账号自动插入的签名。
4. 成功时记录“已填写，待用户发送”。失败或结果不明时提示核实，不自动重试生成多封邮件。
5. 用户手动发送后按现有确认机制标记已发送；助手不可凭窗口消失推断发送成功。

## 5. 技术路线：候选方案，需先验证

- Chrome 扩展通过 Native Messaging 调用 Windows 本地助手。
- 需要新增 nativeMessaging 权限、注册 Native Messaging Host，并允许准确的扩展 ID。
- 不要假定 Foxmail 有已验证的 COM/API。此前没有找到官方公开自动化接口；网上示例不能作为可用性证据。
- 可先验证 Windows UI Automation 对 Foxmail 窗口、地址控件、主题及编辑器的支持；必要时评估焦点/键盘/剪贴板辅助，但必须验证目标窗口和焦点。
- 若使用系统剪贴板中转，应说明实现行为，不读取或记录无关剪贴板数据。需要恢复剪贴板时，避免覆盖用户在操作期间新复制的内容。
- 先做最小验证：仅创建一封未发送测试草稿，确认格式和签名完整，再投入安装器开发。若无法可靠操作编辑器，应说明阻碍，不伪装成已稳定实现。
- 不需要邮箱密码、SMTP 授权码或 OAuth：助手只操纵客户端写信界面。SMTP/API 自动发送属于另一个需求，不在此范围。

## 6. 安装一次、升级与身份

设计目标：每个 Windows 用户首次安装一次，后续普通扩展升级不重复安装。

需要解决：
- 明确助手安装位置和每用户注册方式；尽可能不要求管理员权限。
- Native Messaging allowed_origins 与扩展 ID 绑定；开发版扩展换目录/安装身份可能导致 ID 变化。研究稳定扩展身份或显式重新关联流程，不能忽略这个问题。
- 原生通信协议带版本号、能力信息和健康检查，扩展与助手不兼容时给出升级指引。
- 助手更新、修复和卸载应可追踪，不能遗留无用注册项。
- 重装电脑/浏览器、换 Windows 用户、助手被删除等情况可能需要重新安装或修复；Foxmail 界面升级可能需要适配更新。
- 不承诺永不重装，也不把每次更新要求用户重装作为默认流程。

## 7. 安全性与不干扰要求

- 只接受本扩展来源、限定消息类型、校验字段与长度；不能提供任意命令执行、任意脚本或任意路径访问接口。
- 邮件内容不能拼接为 shell 命令；日志不记录密码、完整正文或无关用户数据。
- 不修改用户已有草稿，不全选覆盖签名，不自动关闭含用户内容的窗口。
- 并发操作、重复点击、焦点被抢、多窗口/多账号时，需有明确的串行或拒绝策略。
- 保留现有防重复记录及“待核实”行为。只读金山文档；不得删除、排序或改动业务表数据。
- 不改变已有 Gmail、COSCO、ONE 功能和用户配置。

## 8. 验收清单

- 首次保存设置可检测未安装，安装后能成功检测，不出现假成功。
- Chrome 重启、助手正常升级、扩展普通升级后无需重复安装或重新配置。
- 点击插件一次，无需手动复制粘贴，Foxmail 显示正确 To/Cc/主题及正文换行。
- 多个 Cc 为独立地址；单柜和多柜正文保持对应关系及可读性。
- 现有签名的文字、图片和格式不被覆盖；不同发件账号的签名不混用。
- 测试中文、英文、特殊字符、不同原始换行，以及 Foxmail 未运行/已运行/已有草稿等情况。
- 助手缺失、版本不兼容、Foxmail 未安装、窗口匹配失败、用户抢焦点时，不发送、不改错窗口、不误报成功。
