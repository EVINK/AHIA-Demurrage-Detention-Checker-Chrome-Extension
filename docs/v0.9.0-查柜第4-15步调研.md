## 二、关键发现：Draydog 有完整的接口，不需要点页面、不需要下载 CSV

Draydog 的网页本身就是调用 `https://api.draydog.com`（接口文档公开）。插件在 Draydog 标签页里用你已登录的身份直接读数据，令牌不离开 Draydog 页面。我用你的账号只读地查了几十个柜子，确认能拿到流程需要的全部字段：

| 流程需要 | 接口字段 | 实测样例 |
|---|---|---|
| Appointed / Bookable | `cycle_state` = `import_appt_booked` / `import_appt_booking` | 账号当前 69 / 9 个 |
| 未 tracking 的柜子 | 查询结果的 `unwatched_containers` | — |
| Hold | `import_status.holds`、`parsed_holds`（Customs / Line / Freight / TMF / CTF / Customs Exam …） | `[" 1H","1A","Customs"]` |
| Closed Area | `import_status.closed_area` | `false` |
| 可提 | `ready_for_appointment`、`available_for_pickup` | — |
| LFD | `last_free_date`、`line_last_free_date` | `2026-11-05` |
| 备注里的 SSL LFD | `note_body` | `"SSL LFD 11/06"` |
| 预约 | `latest_appointment.window_start / window_end / status`（UTC，需转洛杉矶时间） | `2026-11-05T15:00Z` |
| ETA | `vessel_eta`、`import_status.eta` | — |
| Deck / Wheeled | `import_status.wheeled`，加各码头自己的字段：`extra_data["Wheeled/Decked"]`、`location` 含 “(Decked)”、`extra_data.chassis = "DECKED"`、预约的 `move_type = "Decked Import"` | 见左 |

## 三、第 4–15 步逐条结论

| 步 | 能否自动化 | 做法 | 困难 / 风险 |
|---|---|---|---|
| 4 Start Tracking 后重搜 | 能 | `POST /containers/watch/` 加入未 tracking 的柜子；不用重搜，下一次接口查询就是完整名单 | 会改你的 Draydog 账号（新增被追踪的柜子），可能影响套餐计数。**需要你同意插件自动加** |
| 5 下载全量状态 | 能，不用 CSV | 一次接口查询 364 柜（分页），直接得到 JSON | 新加的柜子要等 Draydog 抓到数据，刚加时字段为空，按“未知不填”处理 |
| 6 提柜表基线 | 能 | 同 TH_ReadV2，一个只读脚本读“提柜”整表（A、B、D、G、H、K、L、M、N、P 及分区标记行），按 D 列柜号匹配 | 重复柜号要按规则挑业务行，规则要从你的历史记录里归纳 |
| 7 可提与 Hold | 能 | 纯函数按规则算出 A/B 列目标值 | B 列用语（Custom_H、Line_H、Closed_Area、CEX-1A…）要和 Draydog 的 Hold 类型建对照表；“保留 ETA、卸船等其他备注”需要按片段替换而不是整格覆盖 |
| 8 G/H 摆置车架 | 能 | 按缓存里的 `positionRules` | Deck 的证据在每个码头的字段名都不同（见上表），要逐个码头核对；UI 里的 “(W)” 估计来自 `wheeled`，需要用几个柜子对照确认 |
| 9 K 列 LFD | 能 | 比较 `last_free_date`、`line_last_free_date`、备注日期，取较早 | 备注日期没有年份；“Check Line for LFD” 在接口里对应什么要再确认 |
| 10 M/N 预约 | 能 | `window_start` 转洛杉矶时间，精确到分钟；L 列 PIN 公式不碰 | 已取消的预约（`status=cancelled`）要排除 |
| 11 整行移动 | 能 | AirScript 剪切 + 插入剪切的单元格（你已实测可行），移到“按码头排”下按 P 列归组 | 风险最高的一步。脚本运行时现找标记行和柜号所在行，只移动目标行本身，不写其他行 |
| 12 Bookable | 能 | 同 7–11 | 同上 |
| 13 只改变化的字段 | 能 | 三方比较（Draydog / 当前表 / 缓存），只生成需要改的格子 | 写入时如果那个格子在基线之后被人改过，就跳过并在报告里列出，不回改 |
| 14 重新读回复核 | 能 | 写完再跑一次只读脚本，逐格比对 | 无 |
| 15 缓存与汇报 | 能 | 写缓存 `runs` 审计记录（前后值），插件页显示本轮汇总并发通知 | 后台标签页没法截图，用数据快照代替截图 |

## 四、主要困难

1. **写提柜表是新的权限。** 插件到现在为止对表格只读。第 7–14 步要写，做法是插件生成一个带本轮数据的 AirScript 在提柜表里执行，脚本里先按柜号重新定位行、核对格子还是基线值，才写。
2. **规则的细节在你的历史操作里，不在文字里。** Hold 用语、Deck 判断、重复柜号挑行这些，打算用 Codex 缓存里 142 条已核验记录当测试数据：插件算出来的值必须和你核验过的一致，才放开写入。
3. **Start Tracking 会改 Draydog 账号。** 需要你决定能否自动加。
4. **依赖页面结构。** 金山脚本编辑器和 Draydog 接口变了都会停住，停住时报错，不会猜着写。

## 五、建议的实现顺序

- **A（只读，风险低）：** 第 4–5 步读 Draydog，第 6 步读提柜表，插件页显示本轮 Appointed / Bookable 和各柜状态。
- **B（预览）：** 第 7–13 步算出“打算改哪些格子、移哪些行”，在插件页列出来，不写表。跑几轮和你人工结果对照。
- **C（写入）：** 你确认预览可靠后，加「应用」按钮执行第 11–14 步，写完自动复核。
